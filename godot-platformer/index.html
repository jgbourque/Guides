// STEP_02

Turning code on by removing #

To turn an ability on, you'll remove a single # character in front of a line of code. Here's why that works: in GDScript, a line that starts with # gets ignored by Godot — the computer reads right past it. That's how each of your hidden abilities is currently switched off. Take the # away, and the line starts running.

The lines we'll be turning on look like _glide() or _phase(). These are called function calls — short instructions that say "go run the recipe named _glide that's defined elsewhere in the script." The recipe itself is already written; the call is just the trigger. Adding # in front of a call disables the trigger.

Try the toggle below. Click the button to remove the # and watch what changes:

GLIDE ABILITY: DISABLED
# Remove the '#' below to enable the glide special ability #_glide()

With the # in front, Godot skips this line entirely. The glide ability never runs.

That's the whole concept. Each ability has one line just like this. To turn it on, you delete one character — the #.

One thing to watch
Your code uses spaces at the start of each line to keep its structure. Only delete the #. Leave the spaces in front of it alone. Removing the # alone is correct; removing the # plus a space will cause an error.

Got the hang of it? Below is the same workflow you just watched, written out as a checklist you can follow in Godot itself:

Step-by-step: unlocking glide for real

  1. Open your project in the Godot editor.
  2. Open player.gd using either method above — click the Player node's script icon, or find player.gd in the FileSystem panel (usually bottom-left) and double-click it.
  3. Press Ctrl+F (or Cmd+F on Mac) to open the find tool, type _glide, and press Enter. Godot will jump straight to the line.
  4. You'll land on a section that looks like the snippet below — a helpful comment, then the function call commented out with a #.
  5. Delete the # in front of _glide(). (Just the # — leave the spaces.)
  6. Save with Ctrl+S / Cmd+S.
  7. Press F5 to run the game. Jump, then hold the jump key in mid-air. You should fall slowly with a glide sound.

Where this code lives
The four ability switches all sit inside a function called _physics_process — the part of the player script that runs every frame (sixty times a second) to handle movement and physics. You don't have to fully understand that function to flip an ability on. Just remember: "search for the function name" is how you'll find any of them.

Got it working? You just modded a game. The other three abilities work the same way — but first, a small puzzle: which key do you press to test them?

// STEP_04

Which input triggers what?

Glide was easy because it uses the jump input, which you already knew. But what input is wired to phase? Or teleport? In Godot, this is set in one place: the Input Map — where any kind of input (keyboard keys, mouse buttons, gamepad buttons, joystick axes) gets connected to an action.

Here's how to find it in your real project:

  1. In Godot, click Project → Project Settings… from the top menu.
  2. Click the Input Map tab.
  3. Use the search box at the top to filter — try typing phase or teleport.
  4. Click the arrow next to an action to expand it and see what inputs are bound.

Quick reference
For Player 1, the abilities use: Backspace for phase, Enter for teleport, Down arrow for shrink. For Player 2: Tab for phase, Shift for teleport, S for shrink.

You might have noticed something curious. The Input Map doesn't say "the up arrow makes the player jump." Instead, it says "the up arrow triggers an action called player_1_jump." Why the extra step?

Because that middle step — the named action — gives you flexibility you'd never get otherwise. Click any key below to see what happens:

Three keys all trigger the same player_1_jump action — keyboard, spacebar, gamepad. The code only ever asks "did player_1_jump fire?" It doesn't care which key was pressed. That's why Player 2 can use W while Player 1 uses Up: the code is identical, only the action name differs.

Bottom line: this design lets one piece of code work for any key, any controller, any player. You'll see it everywhere in Godot.

// STEP_05

Unlock the other three

Same trick as glide — just different line numbers. Click each card below as you unlock it in your real project to track your progress:

The full reference

All four switches live in player.gd, inside the _physics_process function. To find each one, press Ctrl+F and search for the function name. Each will look something like this:

# Remove the '#' below to enable the [ability] special ability #_ability_name()

The four function names to search for:

_phase ← the phase ability _shrink ← the shrink ability _glide ← the glide ability (already enabled) _teleport ← the teleport ability
Try them one at a time
Enable just one, save, run the game, see how it feels. Then come back for the next. One change, one test — the way real game designers iterate. If something breaks, you instantly know which change caused it.
// STEP_06

You just learned three real things

These aren't ability-specific tricks. You'll use them every time you mod a Godot game:

  1. The # switches code on and off. Adding it disables a line; removing it enables one. Indentation matters.
  2. The Input Map shows you which inputs do what. Project Settings → Input Map, search and expand.
  3. One change at a time. Edit, save, test, repeat. Always know which change caused which result.
