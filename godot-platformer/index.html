// STEP_02

The hashtag that switches code off

In your game's code, a line with # at the start gets ignored by Godot. The computer reads right past it. That's how each of your hidden abilities is currently switched off.

Try the toggle below. Click the button to remove the # and watch what changes:

GLIDE ABILITY: DISABLED
289# Remove the '#' below to enable the glide special ability 290#_glide()

With the # in front, Godot skips this line entirely. The glide ability never runs.

That's the whole concept. Each ability has one line just like this. To turn it on, you delete one character — the #.

One thing to watch
Your code uses spaces at the start of each line to keep its structure. Only delete the #. Leave the spaces in front of it alone. Removing the # alone is correct; removing the # plus a space will cause an error.
// STEP_03

Unlock Glide in your real project

Now do the same edit in Godot itself.

  1. Open your project in the Godot editor.
  2. In the FileSystem panel (usually bottom-left), find player.gd and double-click to open it.
  3. Press Ctrl+G (or Cmd+G on Mac) and type 290 to jump to line 290.
  4. Delete the # in front of _glide(). (Just the # — leave the spaces.)
  5. Save with Ctrl+S / Cmd+S.
  6. Press F5 to run the game. Jump, then hold the jump key in mid-air. You should fall slowly with a glide sound.

// STEP_04

Which key triggers what?

Glide was easy because it uses the jump key, which you already knew. But what key is wired to phase? Or teleport? In Godot, this is set in one place: the Input Map.

Here's how to find it in your real project:

  1. In Godot, click Project → Project Settings… from the top menu.
  2. Click the Input Map tab.
  3. Use the search box at the top to filter — try typing phase or teleport.
  4. Click the arrow next to an action to expand it and see what keys are bound.

Below is a working simulation of the Input Map, populated with your platformer's bindings. Try searching, and click any action to expand it:

Quick reference
For Player 1, the abilities use: Right Ctrl for phase, Right Shift for teleport, Down arrow for shrink.

You might have noticed something curious. The Input Map doesn't say "the up arrow makes the player jump." Instead, it says "the up arrow triggers an action called player_1_jump." Why the extra step?

Because that middle step — the named action — gives you flexibility you'd never get otherwise. Click any key below to see what happens:

Three keys all trigger the same player_1_jump action — keyboard, spacebar, gamepad. The code only ever asks "did player_1_jump fire?" It doesn't care which key was pressed. That's why Player 2 can use W while Player 1 uses Up: the code is identical, only the action name differs.

Bottom line: this design lets one piece of code work for any key, any controller, any player. You'll see it everywhere in Godot.

// STEP_06

You just learned three real things

These aren't ability-specific tricks. You'll use them every time you mod a Godot game:

  1. The # switches code on and off. Adding it disables a line; removing it enables one. Indentation matters.
  2. The Input Map shows you which keys do what. Project Settings → Input Map, search and expand.
  3. One change at a time. Edit, save, test, repeat. Always know which change caused which result.
